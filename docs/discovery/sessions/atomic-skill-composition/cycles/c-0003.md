## Questions and Answers

**Q1 - Compositional obligation of the skill level (grounded, re-presented
once).** The loop first proposed enforcing adoption partly by requiring every
atom and molecule to have at least one consumer. The user rejected the proxy:
"Why would every atom and molecule have one consumer? That doesn't make any
sense. We're capturing things into small REUSABLE chunks." The loop conceded -
the proxy conflated an atom extracted from duplication, where zero consumers is
a real defect, with a reusable primitive, where zero consumers is normal. A
library unit owes no caller. Re-presented with collapse scoped to the n-0007
inventory. The user then reframed the question entirely: "Take a look at how
things are organized right now. They're already compositional. We're just
formalizing this further." Verified against the tree rather than accepted: all
21 skills already use `## Required References`; 165 reference files exist; 135
reference no other unit, matching the confirmed Atom rule; 30 reference others
and are molecule-shaped. There is no obligation to impose, only structure to
name. Disposition `settled`.

**Q2 - What formalization means (follow-up).** Recommended that every reference
file carries a level wherever it lives, with level a property of the unit rather
than its address; alternative that only shared units under `_base` carry a
level. Answered: the recommendation. Disposition `settled`. Relocation is
therefore never reclassification.

**Q3 - What Chronicler is (follow-up).** Recommended that Chronicler's level is
`skill` and non-routable, preserving the single-Markdown-file rule and requiring
no file moves. Answered against the recommendation: "Chronicle is like a base
skill that would never be used on it's own... I think it's a molecule, where we
have atomic chronicle operations (append for instance)." Disposition `settled`.
This is a decomposition rather than a relabel, and it exposed that the model had
no home for deterministic code.

**Q4 - Where deterministic code lives (follow-up).** Recommended co-location by
basename - `<unit>.md`, `<unit>.mjs`, `<unit>.test.mjs` - preserving the
single-file rule literally and keeping code beside the contract it implements.
Answered: the recommendation. Disposition `settled`.
