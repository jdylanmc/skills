## Error Handling

### No subject supplied

Ask what plan, design, decision, or idea should be interrogated. Do not fabricate a topic.

### Subject is too broad

Identify the breadth and recommend a starting objective or boundary. Ask the user to select it before expanding dependent branches.

### Conflicting answers

Cite the conflicting node IDs and statements neutrally. Explain the material consequence and ask which answer supersedes the other.

### Research fails

Record what was attempted, why the fact remains unresolved, and whether it blocks dependent questions. Ask the user only if they may possess inaccessible information; otherwise mark it blocked or propose accepting it as unknown.

### Tool or permission unavailable

Do not imply that research was completed. Record the limitation, use another legitimate source when available, and distinguish verified facts from assumptions.

### No ready questions

Report whether the tree is waiting on research, blocked, complete, or contains only immaterial uncertainty. Do not manufacture a frontier.

### User requests implementation during interrogation

Explain that implementation is gated on confirmed Shared Understanding. Offer to finish or stop the interrogation first.

### User stops early

Respect the request immediately. Provide a compact partial register, identify unresolved material nodes, and state that shared understanding was not fully confirmed.

### Repetitive loop detected

Stop repeating equivalent questions. Show the unresolved node, explain why it remains open, and offer the user a choice to answer, defer, delegate, accept it as unknown, or stop.

### Unsafe objective

Decline to strengthen the harmful aspect. State the concern briefly and offer to interrogate a safer, legitimate objective instead.
