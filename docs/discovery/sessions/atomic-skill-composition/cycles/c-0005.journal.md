### E-c0005-2 - Two behaviors were lost in the collapse and recovered

Found by auditing removed prose against the units that replaced it, before any
external review returned. Both are recorded because they establish that collapse
is not a mechanical operation.

1. **`write-verified` validated only after writing.** The
   `simplify-technical-language` gate it replaced required staging the candidate
   to a temporary repository-local file and validating it *before* replacing an
   existing artifact. Verify-then-restore leaves a window in which the
   destination holds unapproved content. Staging is now step 3 of the atom.
2. **`breakdown-code-architecture` lost a domain rule**: "a request to inspect,
   map, document, or explain architecture is not by itself approval to write
   files unless it explicitly asks for persistence". The atom owns generic scope
   binding; what counts as a *persistence request* is the caller's domain. It was
   restored to the caller.

The general finding: when N copies of a behavior differ, the union of their
requirements is larger than any single copy. Collapsing to the *most common*
wording silently drops the strictest one. **Collapse must take the union and
then decide, per requirement, whether it belongs to the unit or to the caller.**

### E-c0005-3 - The naming convention, decided under delegation

The user delegated the naming convention explicitly: "For naming convention, I
am OK with whatever your recommendation is", proposing `<purpose>.atom.md` and
`<purpose>.mole.md` as one option.

The suffix form was **declined on executed evidence**, not preference.
`validate-skill-graph.mjs` line 292 sets `stem` to the file name minus `.md` and
line 304 requires frontmatter `name` to equal `stem`, so `resolve-lens.atom.md`
would force `name: resolve-lens.atom`. Line 87's `unitNameOf` takes the **first**
dot-separated segment, so a support file `resolve-lens.mjs` resolves to
`resolve-lens`, which would not be in the registered unit set, and line 115
throws. Any unit with a script would fail the build.

Two further reasons, recorded so the option is not reproposed: a level suffix
duplicates the level namespace, creating a second source of truth for exactly
the fact c-0004 made single-authority; and a *mole* is a distinct unit of
amount of substance, so `.mole.md` names the wrong concept.

**Decided:** `<domain>-<verb>[-<object>].md`, kebab-case, lowercase, globally
unique, no numeric prefix, no level suffix. Domain first, so families cluster
alphabetically in a flat namespace - which is the actual readability win at
scale, and the reason the inventory's verb-first proposals such as
`resolve-artifact-roast-sources` were not adopted. It also matches the shipped
`chronicle-append`, `chronicle-replay`, `chronicler`.

Held in practice by the six units created this cycle: `agent-spawn`,
`approval-gate-mutation`, `review-validate-report`, `review-ste-coach`,
`write-verified`, `write-approved`. Three domains, each clustering.

### E-c0005-5 - A `## Required References` section captures links until the next heading

Discovered by execution during the migration, not by reading.
`validate-skill-graph.mjs` line 8 matches the section heading, and the scan runs
to the next `##` heading or to end of file. Two consequences bit immediately:

- In `synthesize/references/60-simplified-output.md`, a section placed under the
  title captured a prose link from the following paragraph, producing
  `includes mirror drift`.
- In `breakdown-to-tickets/references/70-preview-and-approval.md`, which has no
  later `##` heading, the scan reached end of file and counted a prose link to
  the same unit twice.

The convention that follows: a `## Required References` section contains the
list and nothing else, and is placed immediately before the next `##` heading.
Prose elsewhere in the file refers to a unit by name rather than by link.

This is a real constraint on how a thin `SKILL.md` is written, and it was
invisible until a file was actually wired.
