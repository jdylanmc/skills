## Research Results

### c-0001 - Metaphor analysis of the proposed four-level scheme

Produced by the loop and presented to the user before Q5. Not a user decision
until the user accepted it.

- The proposed scheme `atom -> molecule -> ingredient -> recipe` mixes two
  metaphors. `Atom` and `molecule` are chemistry; `ingredient` and `recipe` are
  cooking.
- In the cooking metaphor an ingredient is the **primitive**. Placing it in the
  third slot inverts the ordering that the word itself implies, so a reader who
  knows what a recipe is will predict that ingredients are the bottom layer and
  be wrong.
- `Recipe` would name a unit this repository and the runtime already call a
  **skill** - `skills/`, `SKILL.md`, routing on `name` and `description`. A
  fourth word for an existing unit adds a synonym, not a distinction.
- Four levels requires four testable boundaries, while n-0001 had not yet
  produced one.

Outcome: the user accepted three levels, `atom -> molecule -> skill`, and kept
`recipe` as the mental model rather than a structural level.

### c-0001 - Atom boundary scenario stress-test

Run during the `/domain-mapping` handoff. Five scenarios; three passed cleanly.

| Scenario | Result |
| --- | --- |
| "Edit a file" - a thin wrapper over an existing tool | Atom. Consistent with the uniform bottom layer chosen in Q2. |
| "Ask one bounded question with a recommendation and an alternative" | Atom. One operation carrying an authored format. |
| "Query the database, then write results to a file" | Molecule. Two operations. |
| "Download a file" that internally performs authentication, retry, and checksum verification | **Ambiguous.** Resolved by ruling that a single operation is judged from the caller's point of view, so internal steps never split an atom. |
| `skills/_base/chronicler/` - build, validate, emit, replay, in a directory with 3 scripts and 2 tests | **Non-conforming.** Multiple operations, so not an atom; not a single file, so not a molecule under the c-0001 form rule. Created node n-0006. |

The stress-test also produced the mechanically checkable atom boundary now in
the confirmed definition: an atom references no other unit of composition, so
the existing dependency-graph validator can decide the question without human
judgment.

## Prototype Outputs

### c-0002 - Derived versus authored reverse links

The user asked whether a `used-by` reverse link could be kept correct by lint.
The loop had objected to `used-by` on three grounds; the analysis conceded one
and kept two.

| Objection | Survives lint? |
| --- | --- |
| The field goes stale silently | **No.** Conceded. `validate-skill-graph.mjs` already verifies that `includes` mirrors the real `## Required References` links, so a reverse-edge check is the same shape. A linted `used-by` is never wrong. |
| Fan-in churn | **Yes.** Adding one skill composing 8 atoms still means 9 file edits, and lint makes the 8 mandatory rather than optional. |
| Parallel-merge conflicts | **Yes, and worse.** `includes` is one-to-many written in the file being edited; `used-by` is many-to-one written into files the author is not editing. An atom used by 30 skills has a line every one of those 30 pull requests touches, and with lint a conflict becomes a build failure. |

The decisive observation: a linter able to *verify* a derived field is able to
*generate* it, from the same graph. The real choice was therefore
authored-and-verified versus generated-and-committed, and the latter delivers
bidirectionality with none of the surviving costs. The user chose it.

Precedent: `doctrine/manifest.md` commits SHA-256 digests, continuous
integration checks them, and `AGENTS.md` instructs regeneration by command.

No prototype has been proposed, approved, or run. This entry records analysis,
not execution.

## Limitations

- `docs/` is untracked in git at commit `e98a372`, so this discovery package is
  currently outside version control. Recorded at session setup on 2026-08-20.
  **Resolved:** committed in `ca9b668`.
- `skills/reinforce-skill/` is untracked and exists in no commit. It is counted
  in the 22 directory entries but is not part of the committed skill set. Still
  open as of c-0004; the user has never decided its disposition.
- **c-0003 digest bookkeeping is unreliable.** Its recorded `exit-state-digest`
  and `exit-root-map-digest` do not reproduce from the files it wrote, although
  `exit-root-lexicon-digest` does, and `git` proves no file changed after the
  single commit that introduced them. c-0004 recomputed and verified its own
  baseline, so drift detection from c-0004 forward is sound. Any comparison
  against a pre-c-0004 recorded digest is not.
- **A delegated survey's completeness claim was false.** The duplication
  inventory's first pass reported "no files were sampled or skipped" while
  having read 140 of 165 files, missing every file in a nested
  `references/**/` subdirectory. It was corrected only because the count was
  checked independently. Treat any subagent self-report of coverage as
  unverified until counted.
- The duplication inventory is a static comparison of Markdown. No skill was
  executed and no behavioral test was run, so "same behavior" is a reading of
  the instructions rather than an observation of what the skills do.
