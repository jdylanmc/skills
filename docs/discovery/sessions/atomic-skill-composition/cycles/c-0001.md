## Questions and Answers

**Q1 - Driving problem (grounded).** Which problem is the model primarily meant
to solve? Recommended reuse and duplication; alternative context economy.
Answered: "Reuse, de-duplication, composability, testability, best practices - I
am putting structure and order on a lose concept." Disposition `settled`. The
answer is multi-objective and explicitly excludes context economy, which
preserves the `AGENTS.md` rule that `includes` is a dependency mirror rather
than a loading directive.

**Q2 - What an atom is made of (grounded).** Recommended a reusable authored
unit of procedure or judgment, excluding bare tool wrappers; alternative any
single operation including thin wrappers. Answered: the alternative, a uniform
bottom layer. Disposition `settled`, against the recommendation. The loop
recorded the accepted cost - a large atom population that the validator must
carry - rather than relitigating.

**Q3 - On-disk form of an atom (follow-up).** Recommended one package directory
per atom; alternative a two-form package-or-catalog split. Answered with a
correction to both: "it should be a single markdown file with consistent
frontmatter across all atoms", and "it's a logical unit". Disposition `settled`,
revising Q3. This diverges from the existing `skills/_base/<name>/BASE.md`
package form and matches the existing flat-file precedent at
`agents/<name>.agent.md`.

**Q4 - Form at the higher levels (follow-up).** Recommended that the single-file
rule bind atoms only, leaving molecules and skills as package directories.
Answered: "Atoms should be a single file. Molecules may compose multiple atoms,
but really they are a single file pointing to atom files." Disposition
`settled`. Molecules are therefore also single files, composing by reference.
The package-directory form is reserved for the invocable top level.

**Q5 - Level count and naming (follow-up).** The user proposed replacing
atoms/molecules/organisms with atoms/molecules/ingredients/recipes, where skills
are recipes that are invoked. The loop presented three grounded objections - the
cooking metaphor places ingredient at the primitive position so a third-level
ingredient inverts it; `recipe` renames a unit already called a skill; and four
levels demands four testable boundaries while none existed yet. Recommended
three levels named atom, molecule, skill, keeping `recipe` as the mental model.
Answered: the recommendation. Disposition `settled`. This revised the anchor.

**Q6 - Adoption success condition (grounded).** Recommended proof by collapse;
alternative declaration and ordering only. Answered: the recommendation.
Disposition `settled`.

Group closed at 6 of up to 12 under the "material fog for the selected node is
resolved" rule rather than the cap. Unused capacity: 3 grounded, 3 follow-up.
